# Changelog

All notable changes to TideWM are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Fixed
- Backdrop capture is now damage-driven instead of re-rendering the whole behind-scene once per glass window on every frame. Each glass or frosted surface keeps its own `OutputDamageTracker` and reuses one texture, so an unchanged scene costs zero offscreen GL work where it used to pay a full-scene render per glass window per frame; an interactive drag, a window moving behind, or a real client commit still recaptures because the tracker sees the geometry or commit change itself. The glass layer's commit is now a rendered-value fingerprint of the capture version plus its own wave phase and corner/frost uniforms, so ambient and reactive tails keep animating while static frost bars and settled glass stop forcing visible redraws. The floating-window and layer-shell passes also build their behind-element list once per output instead of once per glass window, so nine glass windows no longer rebuild the desktop nine times a frame.

### Fixed
- XDG title and app-id changes now flow through Smithay's authoritative callbacks instead of re-resolving every window rule and rewriting opacity/glass caches on every root-surface commit. Identity-only requests update ext/wlr foreign-toplevel clients, IPC, live visual-rule caches, and redraw scheduling immediately even without a following surface commit; title changes alone invalidate tab/depth title rasters, while map-only placement policy is not replayed.
- Foreign-toplevel retirement is now entirely event-driven: every mapped-lifecycle teardown sends `closed` and removes its wlr handle synchronously, so the winit and udev maintenance ticks no longer scan and lock every live handle even when no taskbar client is connected.
- Standalone startup no longer waits synchronously for session-environment and portal-management helper processes before entering the compositor event loop. One named best-effort worker preserves export, foreign-environment cleanup, portal inspection, and conditional restart ordering; a missing or wedged helper can now delay only that integration work, not display/input readiness, autostarts, or shutdown.
- Compositor-owned cursors now prepare and retain stable Smithay buffers instead of reallocating and reuploading their pixels on every rendered frame. The live output's advertised integer scale selects and tags the theme asset while its exact fractional scale controls geometry and hotspot placement, keeping cursor size and click alignment correct and sharp at fractional scale; cached scale variants are pruned when live output scales change or disappear.
- Accessibility keyboard-monitor clients now release their bounded client slot as soon as their grab, watch, modifier, and keystroke state is empty. Unsubscribing or disconnecting also removes only that client from pending release recipients while retaining physical-key suppression until the matching release, so inactive DBus connections cannot exhaust active assistive-technology capacity or leak unmatched key events.
- Wave environment entries are validated before process mutation: empty names, `=` in names, and embedded NUL bytes are dropped with a visible config warning instead of reaching `std::env::set_var` and panicking during startup. Diagnostics identify the key/reason but never echo the value, which may contain a secret; the mutation boundary repeats the guard for programmatically constructed configs.
- Serial-less XDG activation tokens remain available for XWayland and notification compatibility, but now request urgency instead of granting focus. Only a fresh serial from TideWM's own seat can focus a target; stale valid-seat requests keep the existing urgency downgrade and expired tokens remain ignored. Requests for the already active logical window no longer leave it spuriously urgent. This matches the safe default policy in current niri, Sway, and Hyprland.
- Swallowed Classic windows now retain their authoritative output/workspace owner while hidden. If the child closes after leaving its tile and the last output is gone, the parent is restored into that dormant tree instead of being dropped; the existing orphan-output adoption path then migrates it to the first connector that returns. Live child ownership and live fallback workspaces keep their existing precedence.
- Gamma-control resources now keep only Smithay weak output identities and are explicitly invalidated when an output disconnects, control transfers, or applying a ramp fails. A client that ignores the protocol's `failed` event can no longer retain a removed output; later requests and destruction are no-ops, while a valid current owner alone restores the identity ramp on normal destruction.
- XDG flutter detection now ends at the authoritative toplevel-role destruction callback, clearing both timing records and the permanent float exemption before a client can create a fresh role on the same surface. Temporary null-buffer unmap/remap keeps its history, while time-expired counters are pruned without using `Space` visibility as a false liveness test for hidden workspaces, parked groups, or Classic Depth windows.
- Move-grab teardown is now transactional. Classic and Ocean tiled drops mutate layout only after the initiating mouse button is actually released, or after a non-cancelled modifier-swipe ends while unlocked; grab replacement, locking, surface loss, and cancelled gestures perform cleanup and snap-back only. Floating Ocean moves likewise reserve smart reattachment for confirmed completion while always clearing their drag hint and synchronizing the live floating position.
- Closing the Ocean minimap now re-resolves pointer focus at the cursor's unchanged location, so the first click after a keyboard dismissal reaches the surface already under the pointer without requiring a physical motion first. Click-to-travel also suppresses only the compositor-consumed press's paired release, preventing an unmatched release from leaking to the newly focused client; fresh presses clear stale suppression after device or session transitions.
- Caustics texture updates are now transactional: a full-target Smithay render writes into a reusable scratch texture, clears it before blending, and swaps it on screen only after draw and finish succeed. Failed updates preserve the last good texture and visual commit, discard the suspect target, and back off shader/render retries exponentially from the configured effective cadence or the output's live mode cadence. Renderer-context replacement invalidates the shader and both texture slots safely, and the offscreen pass no longer creates a disposable damage tracker and element identity every frame.
- The embedded wallpaper now decodes lazily into a static GLES texture and releases its native pixel buffer immediately after a successful upload, removing a permanent 31.6 MiB CPU copy without reducing source detail. Renderer-context replacement reimports safely, failures are retained and logged once instead of retried every frame, and destination geometry comes from the live transformed and fractionally scaled output rather than treating raw mode axes as logical dimensions.
- Compositor-owned one-line text now stops rasterizing at its live logical clip and uses an ellipsis for the hidden tail. Huge client titles and failed-command messages can no longer drive work or toast allocation from their full input length; toast geometry follows the narrowest transformed/scaled output, rebuilds after output changes, uses checked buffer arithmetic, and retains at most the existing IPC request bound for visual and AT-SPI text. Title commits now invalidate grouped-tab and deep-window caches, while deep schematics avoid cloning titles on cache hits.
- Animated gradient borders now damage only their visible ring instead of invalidating the full window-sized rectangle on every color step. Rounded corners and antialiasing stay conservatively covered, and the border commit follows the rendered angle and opacity directly rather than assuming a fixed compositor frame rate.
- Constant-motion caustics now wake the DRM backend from their configured per-output deadline instead of depending on unrelated client or border damage, and their phase advances no faster than the configured active/idle FPS even while another animation is rendering. A fullscreen window, empty workspace, or startup without an animated border can no longer starve the caustics clock. CRTCs waiting for an estimated VBlank also retain new damage without rendering immediately, keeping no-damage client callbacks bounded by the live output cadence.
- `wavefmt` now treats escaped quotes and Lua block comments with the same lexical rules as Wave itself. Stripping a block comment preserves source offsets and real newlines without inflating line counts, braces and assignments inside comments cannot alter formatter indentation, and `-w` replaces a synced sibling temporary file atomically while preserving the target's permissions and symlink.
- Ripple cleanup no longer depends on rendering an enabled output, exponential easing lands exactly on its endpoint, and arbitrary configured radii cannot overflow rectangle arithmetic. Ocean admission and Ocean-to-Classic migration now use the live zoomed camera in both world axes; migration samples in-flight camera motion, and fullscreen hit testing keeps compositor-scaled content authoritative. Pointer confinement uses the union of live half-open output rectangles, including layout gaps. Tiling gaps clamp safely from the live slot size, and layout-algorithm or migrated-tree changes invalidate stale resize topology.
- Offscreen capture geometry now comes from the live output mode after applying its configured transform, while capture regions stay in the upright coordinate space clients were offered. Rotated and flipped outputs therefore advertise, validate, and render matching SHM and DMA-BUF dimensions. Toplevel captures now size and offset their target from the popup-inclusive bounding box, preventing menus and other popups from being clipped outside the buffer. The regression coverage uses arbitrary mode dimensions rather than assuming any monitor resolution.
- Native DRM redraw propagation is now event-driven instead of waiting for a hardcoded 16 ms global poll. Damage coalesces through a calloop eventfd, each CRTC retains dirty work while a flip is pending, and successful animation frames continue from that output's own VBlank; empty frames retry from the output's advertised refresh period. Mixed-refresh outputs therefore pace independently, high-refresh clients are no longer capped near 62.5 fps, and idle maintenance drops to a slow pass rather than waking at panel rate.
- Binding another `zwlr_output_manager_v1` now receives the current head serial without advancing global configuration state, so an unrelated client cannot invalidate already-created transactions. Stopping or destroying a manager also removes its per-head resources immediately instead of retaining them for future refresh broadcasts.
- Moving an output through output-management no longer overwrites a floating window's restore state with its temporary fullscreen/maximized rectangle. Normal visible floaters still follow the logical output delta, while overridden windows translate their durable floating tag and fullscreen/maximize restore records and let retile derive the live override from the output's new configured geometry.
- Output hotplug now migrates protocol ownership independently of Classic tree traversal. A fullscreen window preempts an existing destination fullscreen before moving, Ocean fullscreen/maximize state follows the fallback connector and receives its live geometry, and parked Classic Depth Deck entries are retagged with the rest of their workspace. When the last output disappears, the first later connector adopts ownership keyed to no-longer-live connector names, so reconnecting through a differently named port cannot strand the Classic session. All geometry comes from the mapped outputs and their configured logical layout; no mode size is assumed.
- Ocean output-sensitive actions now resolve the camera which is actually presenting or interacting with a window, keeping the original `entry_output` only as an admission fallback. Fullscreen/maximize, primary-output selection, XDG move/resize scaling, and window screencasts therefore follow live camera placements with stable largest-visible-area ties. Tiled drags start from the pointer's camera and convert both ends through their real camera origins/zoom, so crossing differently configured outputs keeps the dragged world position and drop target coherent; floating smart-attach likewise uses the release output instead of historical affinity.
- Window frame callbacks and presentation feedback now follow the compositor's actual rendered placements on each output. Hidden Classic windows no longer receive callbacks from every backend render, while Ocean windows use the camera/reef placement they are really drawn through instead of stale `Space` overlap, fixing mixed-refresh pacing and feedback attribution without assuming any monitor size or refresh rate.
- Accessibility keyboard monitoring now records the DBus recipients of each delivered key press and reuses that set for its release. Releasing a grabbed modifier before the modified key therefore cannot make the release disappear, while DBus backpressure still fails open and clears both suppression and recipient state.
- PipeWire daemon loss and incompatible capture-size changes now terminate the affected worker instead of silently creating a replacement node whose ID was never published to the consumer. Mutter-style screencast starts already replace dead handles and emit the new node signal; portal sessions now do the same on their next `Start`, dropping/joining the stale worker outside the session mutex before publishing the replacement node in the normal response.
- Ocean full-tier floating physics now resolves edge collisions in world coordinates. Each entry's live output camera converts the real logical viewport size through its current origin and zoom, so panning, zooming, nested output sizes, and non-origin host placement no longer make bounce edges drift away from the visible viewport.
- BSP trees no longer recurse on the compositor call stack. Insertion, removal/collapse, lookup, swaps, group leaf replacement, layout collection, split hit-testing, resize-path collection, ratio access, and tree destruction now use explicit heap-backed walks/zippers, so a client-created skewed tree cannot move the stack-overflow abort to a different tree operation.
- Detached close-animation snapshots now have configurable count and memory-proxy budgets. `animations.max_closing_snapshots` bounds tiny-window floods, while `close_snapshot_output_budget` derives retained physical pixels from the aggregate area of the live output modes, so nested, HiDPI, and multi-monitor sessions scale from their actual hardware instead of a hardcoded resolution. Oldest snapshots are evicted first and an individually oversized snapshot is not retained.
- When both `XDG_CONFIG_HOME` and `HOME` are absent, Wave config fallback storage is now namespaced by the effective user and verified as an owned `0700` directory before any config is read. Symlinks, cross-user pre-created paths, and unverifiable fallback directories fail closed to empty defaults instead of loading executable config from a shared `/tmp/tidewm-config` path.
- Window groups now operate on the active spatial engine's real BSP owner. Ocean can create, cycle, close, and ungroup tabs inside their reef without consulting empty Classic layouts; parked tabs retain Ocean lifecycle metadata, tab strips follow whichever live output camera renders the group, and Ocean-to-Classic migration refreshes each group's new tree owner. Classic-to-Ocean migration now also records per-window output affinity from the real source output rather than leaving migrated entries ownerless.
- Ocean screen pins now have one authoritative owner instead of a conflicting Classic `pinned` marker. Migrated and newly pinned windows report the same IPC state, fullscreen suspends/restores the Ocean anchor correctly, rule placement and interactive moves rebuild the anchor from the new world rectangle, and dragging no longer snaps a pinned window back to its pre-drag position.
- Wave hot reload is now transactional: the candidate config, globals, and event handlers evaluate in a fresh sandbox, and the live Lua runtime is swapped only after the whole reload succeeds. Removed `script` globals disappear with the old sandbox, while a failed reload leaves every active handler/global untouched. `spawn()`/`action()` are accepted only during an actual event-handler call, preventing the two-pass loader or `tidectl eval` from accumulating delayed side effects. Include resolution now bounds nesting, file count, aggregate source bytes, and generated entries per pass, and failed file evaluation always pops its entry sink.
- Udev output setup now publishes/maps a `wl_output` only after plane discovery and `DrmCompositor` construction succeed, so a transient connector/DRM failure cannot leave a client-visible ghost output. Non-empty DRM render or queue failures also restore the surface's dirty bit, causing the next backend tick to retry instead of leaving that CRTC frozen until unrelated damage arrives.
- Reactive water glass no longer treats its own backdrop recapture as a fresh disturbance. The settle tail still damages the reused capture texture while it decays, but only window movement or an intersecting ripple restarts the envelope, so an idle glass window cannot manufacture an endless capture/redraw loop.
- Ocean keyboard resize now updates the authoritative world-space owner: floating windows write their Ocean rect and tiled windows adjust the nearest split in their owning reef, so the next retile no longer discards the result. Floating resize in both engines now derives minimum and maximum dimensions from the client's current XDG constraints rather than fixed fallback window sizes.
- `tidectl subscribe` now treats a refused auto-discovered socket like the one-shot command: it removes only that stale discovery result, searches again, and connects to the newly discovered live path. An explicit `--socket` is never deleted, and subscribe no longer retries the same path immediately after removing it.
- Runtime layout and master-ratio actions now no-op on an empty active workspace instead of retaining overrides for arbitrary workspace IDs, while declarative `workspace_rule` defaults remain available for intentionally preconfigured workspaces. Cascade state is removed rather than inserted when a workspace has no tiled windows, closing the remaining empty-workspace growth path.
- XDG close events now emit only when a mapped window was actually detached, so a never-mapped role and the later destruction of an already-unmapped role cannot produce missing-open or duplicate-close IPC lifecycles. Screencast window snapshots are now keyed by numeric window ID: map/unmap rebuild membership, while ordinary commits update only the affected window instead of walking and allocating for every mapped window.
- Full-tier floating physics now creates its complete collision body set only while continuous wave forcing or real body motion is active, and removes the set atomically after every body settles; an idle full-tier floater no longer recreates an at-rest body and requests another frame on every backend tick. Ambient float animation is cleared when either spatial engine tiles the window, with animation-state pruning as a defensive backstop, so stale invisible sway cannot keep rendering alive.
- Shared Wave numeric lowering now rejects NaN and infinity before values can reach output scale or other geometry/input settings, and output-management scale validation enforces the same finite-positive invariant. Cascade layout now consumes the actual runtime usable pixels safely when there are fewer pixels than rows or cells, assigning zero-sized exhausted slots instead of panicking or assuming a minimum output size.
- Compositor-owned overlays now consistently use live logical output geometry. The source picker and Ocean minimap translate global pointer input through the selected output's real origin, minimap travel inverts output-local coordinates, and the minimap/overview/depth-deck/source-picker buffers size from logical geometry rather than the physical mode. The source picker scrolls keyboard selection within the rows that actually fit, clipped rows cannot overlap Cancel, and oversized compass cues shrink to the live viewport instead of panicking on inverted clamp bounds.
- Live Classic↔Ocean migration now clears every old-engine `Space` placement before rebuilding visibility, so inactive Classic workspaces cannot retain visible/input-active Ocean mappings. Multi-output Classic workspaces receive disjoint Ocean islands derived from each live logical output geometry and the configured gap, and floating rectangles round-trip through output and reef origins instead of mixing global, local, and world coordinates. Ocean→Classic chooses the nearest reef in both axes and never invents a fallback resolution; an engine change with no live output geometry is deferred with a warning.
- Screencast portal sessions are now bound to their creator's unique D-Bus name and use an atomic `Idle`/`Starting`/`Active`/`Closed` lifecycle. Duplicate object paths are rejected without replacing or cleaning up an existing session, unauthorized `Session.Close` calls return access denied, concurrent `Start` calls cannot launch two workers, and a close/disconnect racing PipeWire startup prevents the late worker from being published.
- Wave execution is now bounded at every untrusted entry point. Config chunks, event handlers, and IPC evals run under scoped instruction/deadline hooks; handlers can queue at most 256 actions; and eval-to-JSON conversion detects table cycles and enforces depth, node, string-byte, and final response-size limits. Infinite loops and recursive/oversized eval results now return errors instead of freezing, stack-overflowing, or exhausting the compositor.
- Long-lived IPC subscribers now retain the connection-limit lease from their initial request until disconnect. Previously the request lease was released during subscription conversion, so opening subscribers sequentially bypassed the 64-connection cap even though ordinary requests and responses were bounded.
- Gamma-control clients can no longer freeze the single-threaded compositor by passing a pipe or socket and withholding ramp bytes. TideWM now enforces the protocol's exact-sized, memory-mappable-file contract before reading, uses positional file reads, and rejects non-regular or concurrently resized inputs as `invalid_gamma`.
- Session-lock composition now fails closed across every capture and udev render path. Per-window screenshots and PipeWire streams are refused as soon as locking starts instead of rendering the target before the shared lock check. The standalone renderer suppresses desktop toasts, close snapshots, transitions, compass/canvas effects, and any pre-lock client cursor surface; only the lock composition and a compositor-owned default cursor can be drawn. Entering the lock also releases in-flight close snapshots so retained client pixels cannot cross the boundary.

### Changed
- **The old-format legacy is fully removed from the code.** The substitution pass (`substitute_variables_in_raw`), the `raw.variables` bookkeeping, the deprecated key/block/action aliases (`spatial_engine`, `default_layout`, `pointer_modifier`, `show_welcome_hint`, `show_config_reload_toast`, `workspace_auto_back_and_forth`, `master_orientation`, `bsp_split_bias`, `cursor_hide_after_ms`, `spawn_at_startup`, `workspace_transition`, `connected_vessels`, `water_glass`, `float_physics`, `classic_depth`, `submap`, `exit-submap`, `duration_ms`, `opacity_duration_ms`, `idle_after_ms`), the `bind X = Y` line form, and the legacy value functions (`rgb()`, `rgba()`, `bezier()`) are gone. A legacy spelling is now an unknown-key warning, never applied. Color parsers accept hex only (`RRGGBB` / `RRGGBBAA` / `#RRGGBB` / `0xAARRGGBB` for shadows). Old configs need the migration documented in `DOCUMENTATION.md` (the mechanical changes listed there); the shipped default and the maintainer's live config are already migrated.

### Added
- `zwp-tablet-v2` drawing-tablet/pen support, closing the second of the config-audit's two protocol-level gaps (the first was `wp-tearing-control-v1`, below). Unlike tearing-control, the pinned Smithay revision carries a full convenience module (`tablet_manager`), so this is mostly real input-dispatch wiring rather than hand-rolled protocol code: `TabletManagerState` registers the global, `TabletSeatHandler::tablet_tool_image` (previously an empty stub that existed only to satisfy `wp_cursor_shape_manager_v1`'s trait bound) now routes a tool's custom-cursor request into the same `cursor_status` the mouse pointer uses, and `tide_core/input.rs` gains real `InputEvent::DeviceAdded`/`DeviceRemoved` handling for the first time in this codebase (previously both fell through to the catch-all no-op, since touch's `wl_seat` capability is advertised once unconditionally rather than hotplug-driven) plus `TabletToolAxis`/`Proximity`/`Tip`/`Button` forwarding, adapted from `anvil/src/input_handler.rs`'s reference implementation. A tablet tool drives the same on-screen pointer a mouse does (`pointer.motion()`, reusing the existing `touch_location` coordinate helper), with tablet-specific axis state (pressure/tilt/distance/rotation/slider/wheel) layered on for clients that understand the protocol; tip-down deliberately does not synthesize a `pointer.button()` press (a tablet client expects only the real tip event for a physical contact) but does route through the same centralized focus resolution `TouchDown` already uses. Verified live in a nested session with a throwaway `wayland-client` binary: bound `zwp_tablet_manager_v2`, called `get_tablet_seat`, confirmed no protocol error and the compositor stayed responsive. Real tablet hardware (`DeviceAdded` actually firing, pressure/tilt reaching a real drawing app) has not been available to test -- nested winit has no way to synthesize tablet input events, the same standing limitation every other grab/gesture-driven feature in this codebase already carries -- but the udev backend needs no separate implementation, since `process_input_event` is backend-agnostic and real libinput tablet events route through the identical code path winit does.
- `wp-tearing-control-v1` protocol support (`src/handlers/tearing_control.rs`), closing the first of the config-audit's two protocol-level gaps. Hand-rolled -- no Smithay convenience module exists for this protocol -- mirroring the shape of Smithay's own `wp_content_type_v1` module almost exactly: a manager global handing out a per-surface object backed by Smithay's `Cacheable` double-buffered state, so `set_presentation_hint` applies on the next `wl_surface.commit` per spec rather than immediately, with the one-object-per-surface guard raising `tearing_control_exists`. **Protocol only, no config surface and no DRM-level effect yet, both deliberate.** Actually honoring the hint means requesting an async/immediate KMS page flip, and the pinned Smithay revision's `AtomicDrmSurface`/`DrmCompositor` hardcode their own atomic-commit flags with no caller-provided override point (confirmed by reading `backend/drm/surface/atomic.rs`, not assumed) -- the underlying `drm-rs` crate does carry the raw `AtomicCommitFlags::PAGE_FLIP_ASYNC` capability one layer down, so this is specifically a Smithay abstraction gap, not a missing ioctl. A `general.allow_tearing`/`rule { immediate = true }` config pair (Hyprland's naming, kept on file for whenever the DRM half becomes buildable) would be dead config with nothing to gate today. Verified live in a nested session with a throwaway `wayland-client` binary: bound the global, created a surface, `get_tearing_control` + `set_presentation_hint(async)` succeeded with no error, and a second `get_tearing_control` on the same surface correctly killed the connection with the exact `tearing_control_exists` protocol error while TideWM's own process stayed alive and healthy.
- `layer_rule { }` gained `blur` (Hyprland's `layerrule = blur`), closing out the layer-rule breadth from the config customization gap audit. Frost-glasses the matched surface's own backdrop, reusing R2's per-window backdrop-capture pipeline generalized to an arbitrary layer surface: `Smallvil::capture_layer_backdrops` (the layer-shell analog of `capture_floating_backdrops`) and `layer_glass_elements` (the analog of `glass_layer_elements`) key into the same `backdrop_textures` map windows use, since `WlSurface` keys never collide between a window and a layer. `append_layers` picks up the same `skip` slice `desktop_render_elements` already threads through `append_windows`, so a bar's own backdrop capture omits the bar itself for free instead of needing a second skip-set. Gated on the global `frost.enabled`, not `water_effects` -- this is general decoration, matching the shadow/rounding/border precedent, not part of the water identity. `layer_shell.rs::layer_destroyed` now removes the surface's `backdrop_textures` entry, same as the existing window-unmap cleanup -- without it, a blur-enabled layer client that's opened and closed repeatedly (any launcher) leaked one full-rect GLES texture per destroy, since nothing else ever pruned that map for a layer surface. **No `ignore_alpha`, and it's a real gap, not a settled non-issue** (an earlier pass reasoned it away and that reasoning was wrong -- caught before it shipped as fact): the captured frost rect is sized to the surface's full negotiated `layer_geometry`, not a bounding box of its actually-opaque pixels, and renders behind the surface unconditionally, so a layer client whose logical size is much larger than what it visibly draws (Hyprland's own motivating case, an invisible full-output click-catcher) would still blur the whole area behind it. Doesn't affect an ordinary bar/launcher sized to its own content, which is why it shipped without the knob; see AGENT.md's layer-rule section for the full correction. Verified live in a nested session: real `rofi` with `layer_rule { namespace = rofi, blur = true }`, a `grim` capture through TideWM's own `wlr-screencopy` showed the wave wallpaper visibly softened behind the launcher panel compared to outside it; a 40-cycle open/close soak on a release build held `Pss` flat (`smaps_rollup`), confirming the leak fix. The udev/DRM backend wires the identical two call sites but hasn't had its own real-hardware pass this session.
- `layer_rule { }` gained four new effects, continuing the config customization gap audit: `z_order` (reorders a matched namespace within its own layer-shell stratum, Hyprland's `order`), `dim_around`/`dim_amount` (dims every non-fullscreen window, lower layer, and the wallpaper while a matching Overlay/Top surface is mapped, Hyprland's `dimaround`), and `above_lock_screen` (keeps the matched surface rendered on top of the session-lock surface, Hyprland's `abovelock`). `z_order` sorts `desktop_render_elements`' per-stratum layer list with a stable `Reverse` key, default 0, so an unconfigured namespace keeps its natural mapping-order stacking. `dim_around` inserts one full-output `SolidColorRenderElement` (a new `Dim` variant on `OutputRenderElements`, cached per-output the same way `lock_blank` already caches the lock screen's own blank fill) directly behind the Overlay/Top pass. `above_lock_screen` is deliberately render-only: the matched surface is pushed into the shared `lock_render_elements` (consumed by both backends and the screenshot/screencast capture path alike) ahead of the lock surface itself, but `surface_under` is untouched, so input still never reaches anything but the real lock surface while locked -- this cannot be used to route input past the lock. A real gap this surfaced and fixed in the same pass: `capture.rs`'s locked-branch `excluded_rects` used to be unconditionally empty (there was nothing to exclude, since no layer content rendered while locked at all); now that `above_lock_screen` surfaces do render there, a screenshot/screencast taken while locked still blacks one out if it also sets `block_capture`, closing the same "recording could see what a live view of the screen wouldn't" hole `block_capture` exists to prevent in the unlocked path. `window_role`/`window_type` remain a permanent gap, not addressed here -- see AGENT.md's audit section. Verified live in a nested session: two overlapping layer clients confirmed `z_order` reverses natural mapping-order stacking; a `grim` before/after pair confirmed `dim_around` visibly darkens the wallpaper; and a real `hyprlock` (`ext-session-lock-v1`) session confirmed an `above_lock_screen` layer surface stays visible over hyprlock's own lock UI in both the live frame and a `grim` capture of it, with the fail-closed session teardown still firing correctly when the lock client was killed.
- **The Wave config format rewrite (the "Make waves with Lua" engine).** The line-based grammar is removed; Wave is the only grammar, and it has a new spine: the file is data on the surface and Lua underneath. `@name = value` defines a variable (`@` never appears anywhere else), `$name` references it in bare strings (`$` never appears anywhere else), quoted strings are fully literal (`"$HOME"` in a spawn command is verbatim text, and an undefined `$name` is a compile error with the fix in the message). Binds are node form: `bind $mod+Q { close-window }`, one action per line or comma-separated on one line, and `bind()` is the same registration callable from `fn` macros, `for` loops, and `script { }` blocks -- one registry, two surfaces. Values are typed: colors (`#8EDDFF`) and durations (`600ms`, `1.5s`, `90m`) are real Lua values with math (`600ms * 2` is `1200ms`, `primary.darken(0.35)` and `primary.lighten(0.15)` derive a palette), lists are real lists (`spawn = [waybar, "swaybg -i ~/wallpaper.png -m fill"]`), and every duration key accepts units (`cursor_hide_after = 2s`) with the legacy `_ms` spellings as aliases. Blocks expose their bodies as Lua tables, so `theme.primary` reads as an expression and sibling fields resolve inside the block. Multi-file includes, the merge policies, hot reload, and the persistent file/line error panel all carry over unchanged, and the reload path now diffs the old and new entry lists per section so a no-op save does zero window-state churn (the reload log says exactly what changed: "2 keys changed (gaps, border), binds +1 -1 ~1"). `on "event" { }` blocks react to the session (window/workspace/focus/urgent/depth/config events) with the live `tide` table -- backend, GPU vendor, outputs, workspace -- refreshed first, and `spawn(cmd)`/`action(str)` inside a handler queue actions that run after the dispatch. `tidectl eval <expression>` evaluates on the running session's Lua (`tidectl eval "theme.primary"`), and the same `tide` table powers hardware conditionals at load time: `if tide.backend == "udev" and tide.gpu.vendor == "nvidia" then ... end` is a real conditional, tested end to end. `wavefmt` (built alongside `tidectl`) formats any `.wave` file canonically, `-w` rewrites in place, `-c/--check` fails CI on unformatted files. The full rationale, the desugaring contract, and the honest rough edges live in the new `WAVE.md`; `DOCUMENTATION.md`'s config reference is updated to the new syntax throughout. - `rule { }` gained two new match criteria, `pid` and `xwayland`, the first step of a wider customization-gap audit against Hyprland/niri/sway/DriftWM (see AGENT.md's new "Config customization gap audit" section). `pid = <n>` matches a window's real client PID (sway's `[pid=...]` criterion) via the existing `Client::get_credentials` path `swallow` already relies on. `xwayland = true|false` is a tri-state match telling an X11 window apart from a native Wayland one (Hyprland's `xwayland:1`/`xwayland:0`) -- since every X11 app arrives at TideWM as one of `xwayland-satellite`'s own Wayland surfaces (see the XWayland section above), there's no protocol marker to check; instead `Smallvil::xwayland_satellite_pid` (captured once in `main.rs` right after `xwayland::setup` returns) is compared against a surface's own client PID. Either field alone is now a complete, standalone identifying criterion, same as `app_id`/`title` -- a rule with none of `app_id`/`title`/`app_id_regex`/`title_regex`/`pid`/`xwayland` set still matches nothing, extending the existing "blank rule is a config mistake" guard rather than replacing it. `resolve_window_rules`'s ~20 call sites across `state.rs`/`handlers/xdg_shell.rs`/`capture.rs` all thread the new `pid`/`is_xwayland` values through alongside the existing `app_id`/`title` pair -- mechanical but real, since a rule using either new field would otherwise silently apply at map time but not at the later per-frame effect-resolution sites (frost/shadow/viscosity/opacity/etc.) that call the same function. Verified live in a nested session: `rule { xwayland = true, float = true, opacity = 0.55 }` correctly left a spawned `kitty` (native Wayland) tiled while a spawned `glxgears` (X11, routed through satellite) floated, confirmed via `tidectl windows --json`.
- `rule { }` gained a third new match criterion, `urgent`, continuing the same customization-gap audit. Unlike `pid`/`xwayland`, this one is meant to flip after a window is already mapped, so it needed the audit's "not a one-shot" gap fixed for real, not just a match field: `Smallvil::mark_urgent` and the urgent-clear branch of `reconcile_keyboard_focus` both now re-resolve the affected window's opacity/glass immediately, instead of only at map time or the next config reload. Every other resolver (viscosity, sway, depth exemption, frost/shadow/rounding/border overrides, ripple config) already re-resolved fresh on every use, so those pick up urgent changes automatically with no extra plumbing. Landed alongside a cleanup: the ~16 call sites that each rebuilt `(app_id, title, pid, is_xwayland)` before calling `resolve_window_rules` now go through one shared `Smallvil::resolve_window_rules_for(surface)`, so a future match criterion only needs wiring in one place. `window_role`/`window_type` (sway/Hyprland's X11-only `WM_WINDOW_ROLE`/`_NET_WM_WINDOW_TYPE` criteria) were investigated and are a permanent gap under the current xwayland-satellite architecture, not a TODO -- see AGENT.md's audit section for why.
- `workspace_rule { }`, the audit's other mechanical gap: per-workspace-number overrides (Hyprland's `workspace_rule` block), matched the same way `workspace_gaps` already addresses a workspace -- raw number, any output. `layout` sets a per-workspace default tiling algorithm (`Layouts::algorithm`'s fallback chain now checks an explicit runtime `layout:<algo>` override first, then this, then the global `default_layout`); `border`/`rounding`/`shadow` layer in as the base a matching `[[window_rule]]`'s own override builds on for a window living on that workspace (`Smallvil::workspace_of_surface` resolves tiled-or-floating membership); `on_created_empty` runs a command the first time the workspace is switched into with zero windows -- fired once per (output, workspace) for the process lifetime, the closest honest analog to Hyprland's real create/destroy lifecycle given TideWM's workspaces always exist as addressable numbers rather than being created on first reference. `default_name` isn't a field here -- the existing top-level `workspace_name` key already covers naming a workspace unconditionally. Verified live in a nested session: `tidectl workspace:3` against a workspace_rule naming workspace 3 correctly created the `on_created_empty` command's marker file exactly once, and `tidectl workspaces` confirmed the switch landed with zero windows.
- `adaptive_sync = off|on|on-demand` config surface (global plus a per-`[[output]]` override), the audit's VRR item -- **config and capability query only, the actual toggle is deliberately not wired up yet.** The udev backend now queries and logs each connector's real `DrmSurface::vrr_supported()` result (a pure read, no atomic commit) alongside the resolved config value; confirmed compiling clean against the pinned Smithay revision, which exposes VRR as a maintained `vrr_supported`/`use_vrr` wrapper rather than raw property manipulation. `use_vrr` itself is held back deliberately: Smithay's own source notes a real-hardware HDMI flicker quirk next to that API, and this codebase's own history (the 0.15.1 `TileMoveGrab` freeze, the S4.5 Ocean freeze) says a wrapper compiling clean and a wrapper being safe on a specific real GPU are different claims -- the second needs the maintainer's own udev/DRM session, which this sandbox has no DRM master to provide. See AGENT.md's audit section for the full reasoning and what's left.
- `popup { }` block giving TideWM's own popup chrome (the config warning panel and toast) optional overrides on the auto-derived theme: `border_width` (defaults to `border.width`, clamped into the 1-4px band a small pill can carry), `border_color` (defaults to the same accent gradient window borders use), and `radius` (defaults to the average `[rounding]` radius). Every field is optional -- set the ones to pin and the rest keep following the theme. This is the escape hatch when the auto theme doesn't fit: previously the only way to change a popup was to change window decoration globally.
- `focus-app:<app_id>` and `close-app:<app_id>` actions, the dock/taskbar's "smart open" primitives. `focus-app` focuses the app's most recently relevant mapped window (preferring one on the active workspace) and gets the camera there itself: Classic switches the workspace first, Ocean travels the camera to the window -- the bar just calls it, no workspace bookkeeping. `close-app` sends a graceful `xdg_shell` close request to every mapped window of the app, the dock's "Quit". Both no-op when the app has no mapped window; the caller launches it when it has none (the dock's left-click on a closed pin does exactly that). Reachable through any existing action path: keybind, `tidectl`, IPC.
- `tidectl subscribe [event...]`, the streaming half of the IPC story. The subscribe mode was compositor-side only, so a reactive widget had to speak raw socket JSON to use it; now the CLI exposes it directly: `tidectl subscribe` opens a long-lived connection and prints one `{"event": "<kind>", "data": ...}` line per change (workspace, focus, window, urgent, depth, config -- no event names means all) until TideWM exits. A bar reads it as a persistent process and updates instantly instead of polling the one-shot queries every second; the QuickShell Tide rice was rebuilt on exactly this, replacing its four fixed-rate `tidectl` polls (workspaces/focused-window/windows every 1.2s) with one event stream plus on-demand refetches -- workspace switches, focus moves, and title updates now land in the same frame they happen, at a fraction of the old query load.
- Floating-window ocean physics, `full` tier (spatial roadmap F1's second and final tier, completing F1). Adds real mass, inter-window collisions, and a continuous traveling-wave field on top of `light`'s closed-form bob-and-drift: each `full`-tier floating window becomes a small damped mass-spring-damper body (`crate::float_physics::FloatBody`) with real velocity state, stepped by a fixed-timestep (120Hz, clamped substeps) integrator driven from both backends' existing ~60Hz frame timer rather than a second event loop. `float_physics { tier = off|light|full }` replaces the old plain `enabled` boolean (still accepted as a legacy `true`/`false` alias for `light`/`off`, globally and per `rule { float_physics = ... }`). `full` reuses `light`'s `frequency`/`damping`/`max_offset`/`response` knobs as the spring's stiffness/drag/displacement-cap/kick-response rather than adding a parallel set for one more tier, and adds `restitution` (collision bounciness, default 0.3) and `bounce_off_edges` (default true, bounces a body off its home output's edge like a basin wall). The three existing kick sources (drag, window mapping, workspace-transition wave) feed the same bodies as velocity impulses. A new `float_physics.wave { }` sub-block (`enabled` default true, `amplitude`, `wavelength`, `speed`) is a continuous forcing every `full`-tier window is spring-pulled toward, keyed by each window's own world position so windows spread left to right visibly ripple in sequence rather than bobbing in lockstep -- deliberately not a manual per-window toggle like `light`'s `toggle-float-ambient`, since the wave is what makes the tier "full." Per the design conversation: displacement stays hard-clamped to `max_offset` exactly like `light` (this is render-offset-only, so unclamped drift would mean a click lands where the window visually isn't), and collision impulses exchange only on approaching relative velocity, never on positional overlap -- two windows a user has deliberately stacked at rest exchange nothing, avoiding the "naive AABB-separation solver explodes a resting stack apart" failure mode. Mass is derived from window area (a big window shoves a small one). With the wave field on, the simulation ticks forever by design (the roadmap's "first feature that opts into ticking every frame"); with it off, a `full`-tier body still decays to rest and gets pruned from the frame pump exactly like `light`. Bodies are created lazily for any floating window resolving `full` (not only on first kick, unlike `light`, since the wave needs something to push on immediately) and pruned on unmap, on losing floating status, or when a rule/hot-reload change moves a window off `full`. Pure unit tests cover the integrator's settle-to-rest and never-settle-while-forced behavior, the hard position clamp, collision impulse exchange (approaching exchanges, resting-overlap and separating both exchange nothing), and edge bouncing. Live-verified in a nested session: two real, deliberately-overlapping `kitty` clients visibly separated beyond their configured overlap under wave forcing across several `grim` captures a couple of seconds apart, continued drifting throughout under `full` with the wave on, and a hot reload that disabled the wave field left them intact and undisturbed with no crash; PSS stayed flat (~88MB) across the whole run. The standalone udev/DRM backend shares the same tick call site as winit but has not had its own real-hardware pass yet.
- Bioluminescent edge-glow compass for the Ocean engine (spatial roadmap S5's first slice). A window outside the output camera's viewport leaves a soft glow at the viewport edge in its direction: urgent windows glow bright cyan in any direction, physically deep (sunk or lower-reef) windows glow cool blue below. Nearer windows glow brighter; the cue fades to nothing at the configured `max_distance`. The cues are ambient and render-only -- camera travel stays on the existing pan/zoom/bookmark/depth actions, there is no click-to-travel, and no element is produced at all when nothing is off-screen, so an idle desktop ticks zero frames. One analytical GLES pixel shader, no texture or framebuffer, and a 16-cue cap so a crowded world cannot grow the element list. Configurable through the top-level `compass { }` block (`enabled` defaulting true under Ocean, `urgent_color`, `deep_color`, `max_distance`, `size`, `alpha`, `shape`); `water_effects` remains the master bypass. `shape` selects circle/arrow/chevron/ring/diamond for each cue, all drawn analytically in the same shader (no new textures); arrow and chevron point toward the window. Deep cues that are off to the side rather than below the viewport now glow too -- the earlier "deep only points down" restriction was an artifact of the first slice, not an intended limit -- and each cue's screen-space center clamps inside the output bounds so the full glow rect stays visible instead of half-clipped at the edge.
- Whole-world overview minimap for Ocean (spatial roadmap S5's other half, alongside the compass). Hold the configured `minimap.key` (default `Super+Space`) to peek: a schematic map of every window in the shared world, plus every connected output's current camera viewport, scaled to fit the triggering output. Click a window or region while still holding to travel that output's camera there and dismiss; release without clicking just dismisses. Reuses `overview.rs`'s dark-panel/labeled-box CPU-composited-texture style directly (same rasterization primitives, now `pub(crate)`) rather than inventing a second visual language, and reads window rects from the same `Ocean::world_layouts` source the compass uses, so the two stay consistent about exactly what's off-screen. Hold-to-peek is new input plumbing, not an ordinary fire-once keybind: `input.rs` tracks the configured chord's held state directly (checked from the closure's already-updated `ModifiersState` each key event, not a separate `pressed_keys()` read, and re-verified on every event rather than waiting on one specific release -- so a release eaten by host-focus-loss or a VT switch, the same class of gap `release_stuck_keys` already exists for, can't strand the peek open) and short-circuits pointer motion/button events into resolve-and-travel while a peek is open, consuming them fully rather than forwarding through `pointer.button()` -- the same call that runs grab dispatch, and the reason this stays clear of the `TileMoveGrab`/`sync_visible_floating_window` freeze class already in this project's history: the peek's own `last_location` is fed from ordinary motion events, never a `current_location()` read from inside a grab callback. Configurable through the top-level `minimap { }` block (`enabled`, `key`); deliberately **not** gated by `water_effects` unlike the compass -- it reads as navigation utility rather than a visual effect. Two real bugs caught in review before this shipped, not just implementation notes: the chord's press handler originally intercepted the key as soon as it matched, before checking whether a peek actually opened -- under the *Classic* engine (`minimap` is Ocean-only) that meant the same combo silently swallowed every press with zero effect and shadowed any ordinary user keybind on it, for nobody's benefit; fixed by only intercepting once `open_minimap_peek` has actually populated the peek. And `open_minimap_peek` didn't refuse to open while the pointer was already grabbed, so holding the chord mid-drag and releasing the mouse button would route the release through the peek's own consume-and-return path instead of `pointer.button()`, starving whichever grab was live (`MoveSurfaceGrab`/`TileMoveGrab`/etc.) of the release event its commit logic waits for -- fixed with the same "don't start while the pointer is already grabbed" guard `modifier_pan_fingers`'s own gesture-start already uses -- narrowed to exclude an ordinary popup grab (any open client dropdown), which doesn't carry the same release-starvation hazard, so a stray open menu doesn't needlessly block the peek from opening. Verified: full test suite (226 tests, 3 new covering the world/canvas transform round-trip including an empty-world degenerate-scale guard) plus a nested-session smoke test (clean startup under Ocean, config block parses with no warnings, window spawn/track unaffected, clean shutdown, no orphaned processes). **Live-verified the same session** (nested winit, real hold+click): held the trigger, clicked a drawn window box, the camera traveled there correctly. Three visual presets followed the same live pass, asked for directly ("decorate it much more, with presets that can be edited a bit like colors"): `plain` (the original flat schematic, unchanged), `bioluminescent` (new default -- deep-water gradient backdrop, rounded glassy window boxes, a cyan/teal glow rim reusing the compass's own palette, urgent windows highlighted in the same accent as the viewport beacon) and `glass` (frosted, neutral drop shadow instead of a colored glow). `minimap.preset` picks the baseline; `background_color`/`window_color`/`accent_color` still override individual fields on top of it, the same shape `compass`'s `shape` + `urgent_color`/`deep_color` already established. Rounded corners and the soft glow/shadow rim reuse `toast.rs`'s `rounded_rect_coverage_local` (now `pub(crate)`) and `ui_theme::mix`, the same rounded-box-with-soft-shadow technique the toast card already uses. **A real rendering bug caught and fixed during the live pass, not just in review:** the rim/glow initially only appeared at a box's rounded corners, invisible along its straight edges -- `rounded_rect_coverage_local` only computes true SDF falloff near a rounded corner; along a flat edge it reports "fully inside" for both the expanded glow rect and the original box, so subtracting one from the other canceled to zero everywhere except the corners. Fixed by painting the glow directly wherever a pixel falls outside the original box's own axis-aligned bounds, the same "paint the full expanded rect, let the opaque fill cover the inside" approach `toast.rs`'s own card shadow already uses -- confirmed live afterward: a continuous halo around every box, not corner brackets.

Starting the configured modifier+move or modifier+resize gesture on a reef tile detaches it at the exact same world rectangle and continues as a zoom-aware free drag; `toggle-floating` returns it to local tiling. Dragging genuinely empty canvas pans the camera directly at any zoom. - Animated water-glass refraction. The distortion was a fixed sine/cosine offset since R1; the shader now takes `u_phase`/`u_amp` uniforms with three motion modes behind a new `water_glass { }` block: `static` (the original fixed look), `reactive` (default: energized by disturbances -- the window moving, the backdrop recapturing, a ripple passing underneath -- settling back to still over `settle_ms`), and `ambient` (constant drift, ticking frames while glass is visible by design). Reactive preserves the idle-zero-frames rule: disturbances are derived from state deltas in the render walk itself (rect/backdrop-commit compare plus ripple intersection), not hooked at N call sites, and `has_active_animation` only keeps the pump alive while a settle envelope is actually above zero. A fresh glass window starts kicked, since mapping disturbs the water it lands on.
- Ambient caustics overlay (`src/visual/caustics.rs`). - Live spatial-engine migration (spatial roadmap S6). `spatial_engine` was startup-only: a hot reload that changed it force-reverted the key and demanded a restart, which made testing Ocean genuinely tedious. - Floating-window ocean physics, light tier (spatial roadmap F1's first tier). Generalizes `sway.rs`'s 1D lateral kick into disturbance-driven 2D bob/drift: a closed-form decay-to-rest record kicked by a drag, a window mapping, or a workspace-transition wave crossing the output, render-only -- logical geometry, focus, and hit-testing stay exactly where they are, matching the roadmap's cosmetic-not-logical decision for this feature. Config-gated through `float_physics { }` (`enabled` default false, `response`, `max_offset`, `frequency`, `damping`, `bob_ratio`, `radius`, `falloff`) plus a last-match-wins `rule { float_physics }` override; `water_effects` remains the master bypass. - Caustics idle-decay tiers. The always-on caustics overlay, when `caustics.fps` is set above zero for constant ambient drift, now steps its effective frame rate down through configurable tiers as the desktop sits idle -- default 30fps after 5 minutes, 15fps after 10, and 10fps after 30 -- driven by a new `last_activity` timestamp reset on every real keyboard/pointer/touch event reaching `process_input_event`. `caustics.idle_fps`/`caustics.idle_after_ms` are parallel, ascending space-separated lists; either being empty disables the decay and leaves the rate at `fps` for all idle time. ### Changed
- The auto-float heuristic at map time now matches sway's `wants_floating` rule instead of a stricter both-dimensions check. A window with *either* dimension pinned by min/max size (both min dimensions nonzero, and `min_w == max_w` or `min_h == max_h`) floats on open: a splash screen, a fixed-size utility panel, a small bootstrapper (Discord's), an OBS-style source picker. Previously both width *and* height had to be exactly pinned, so a window fixed in one dimension only (or a launcher that opens small) fell through and got tiled into a slot it could never fill. niri's own rule is the height-only variant; the OR version is the defensible match for a BSP layout, which varies both dimensions. `rule { tile = true }` remains the escape hatch back to tiled per app.
- The shipped default config is reworked around a single `SUPER` modifier and split into two real files on first boot: `config.wave` now genuinely `include`s `keybinds.wave` (previously only a commented-out suggestion), and the first-boot generator writes both side by side -- an already-present `keybinds.wave` is never clobbered, and the just-written pair is loaded through the real disk-resolving path so the include works on the very first boot, not just the next reload. Every bind hangs off one `$mod = SUPER` variable, so rebinding the primary modifier is a one-line change. The generated `config.wave` is much shorter: the wall of commented-out effect/tuning blocks moved out (that catalog lives in DOCUMENTATION.md), leaving the core keys, the water master toggle, layout, input, xwayland, and commented examples for monitors/autostart/env/window rules, organized under `~~~`-style section headers. `show_welcome_hint` sits at the top of the file with a note that setting it false or deleting the line dismisses the first-boot card for good. ### Fixed
- The rounded-rect SDF behind the toast and config-warning panel no longer reports a point as fully covered when it sits far outside the shape. The `dx <= 0.0 || dy <= 0.0 => return 1.0` shortcut treated "flat along one axis" as "fully inside" regardless of the other axis, so a point directly above or below the flat middle of an edge read as full coverage at any distance -- the panel's fill, shadow, and border silently ignored their own vertical bounds across nearly the whole card width, leaving almost no margin or rounding except right at the corners. Each axis now floors at zero before the corner distance is computed, so flat regions stay at 1.0 while a genuinely outside point falls off correctly. The same fix landed in both renderers, each with a regression test.
- A tiled window that stays mapped but refuses the tiled size now floats instead of hanging broken in its slot. The flutter-storm guard catches clients that null their buffer and remap; a second class never unmaps at all -- it just keeps committing buffers at its own size (mpv with a locked video aspect renders at 944x531 inside a 944x1016 tile, half-empty, forever). `retile_with_viscosity` now records the tiled size it promises each window, and the commit path (`note_tiled_size_refusal`) counts consecutive commits that miss that size: a couple of stale frames after a resize are normal grace, but a streak that survives 3 mismatches over 500ms is a refusal, and the window is floated immediately and marked `flutter_floated` so it is never tiled again. The map commit is never counted (it's the client's natural size, sent before it saw the tiled configure), active pointer grabs are exempt (mid-drag commits legitimately lag the latest configure), and the tracking resets on a matching commit or a changed expected size. Logs `tiled size refused persistently, floating surface instead of tiling` with app_id/title and both sizes when it fires. Live-verified on real hardware: mpv opened via thunar, tiled to 944x1016, committed 944x531, floated by the guard within the session log (`app_id=mpv expected=944x1016 actual=944x531`).
- The map/unmap "flutter storm" no longer loops or crashes the compositor. A client that nulls its buffer and immediately maps again, over and over -- a video player refusing a tiled size re-realizes its surface on every refusal -- used to cycle `Map -> retile + tiled configure -> null -> Unmap -> retile -> Map -> ...` with no bound: every cycle re-sent the tiled configure the client kept refusing, and the storm could trip the retile-path state invariants. The commit path now tracks per-surface map/unmap timing (`lifecycle_flutter`/`flutter_floated` in state.rs); after three quick flips inside a second, the surface is marked flutter-floated and `map_toplevel` floats it on every subsequent map (skipping the tiled configure entirely), which is the one outcome the client has nothing to refuse. A single real minimize is one flip and never trips this. Also hardened the two latent crash sites the storm exposed: `sync_visible_floating_window`'s unconditional `unwrap` on the floating tag is now a graceful skip, and the flutter tracking prunes itself to windows the compositor still tracks.

App ids are conventionally lowercase but real clients vary, and xwayland-satellite synthesizes them from free-form `WM_CLASS` -- a rule written as `mpv` silently missing a client reporting `MPV` is exactly the "app that must float, opens tiled" report. Titles were already case-insensitive substring matches; app ids now match case-insensitively too.
- The screencast source picker is now a proper KDE-style dialog instead of flat rows. Keyboard navigation (arrows/Tab/Enter/Escape) is unchanged.

- The screencast PipeWire worker now survives a `pipewire` daemon restart instead of dying silently. The worker listens for the core error event and treats a failing loop fd the same way (the two ways a dead daemon surfaces), then reconnects with a fresh core, stream, and format negotiation after a one-second backoff, up to ten attempts -- xdg-desktop-portal-wlr's exit-and-restart semantics without the process death, so a `systemctl --user restart pipewire` no longer leaves an OBS capture stream hanging in a dead state. Only after the retries are exhausted does the worker stop, which the portal already heals on the app's next `Start`.

- Ocean ripples anchored to a window now land on the window itself at any camera zoom or pan. `spawn_ripple` resolved the window's world rect but rendered the impulse in output-local view space, so the two agreed only at the identity camera (origin 0, zoom 1): zoomed in or out (or after the camera crossed empty space), a ripple could appear far off its window or entirely off-screen. The anchor and peak-radius rect now go through the same `world_to_view_rect` the placement builder uses, so the ripple matches where the window is actually drawn, sized to its on-screen extent.
- The caustics overlay renders at 1/4 resolution into a cached offscreen texture and upscale-blits it to the output instead of running its procedural shader over the full output every frame. The pattern is low-frequency and resolution-independent (the shader works in output-relative coordinates), so the blit reads identically at roughly 1/16th of the fragment cost -- `caustics.fps > 0` is now affordable on integrated graphics instead of being a frame-rate tax, which is the difference between "caustics animating over a still desktop" and "caustics frozen at 1fps or nuking the compositor." The texture is reused across frames (one ~1/4MB per output, reallocated only on a size change) and re-rendered only when the sample actually changed, so a static sample skips both the pass and the blit. Also: `caustics.intensity = 0` skips the element entirely (an invisible pass was still composited), `caustics.fps > 0` with `speed = 0` no longer keeps the frame pump alive for a pattern that never changes (it only produced an EmptyFrame retry churn), and an idle-decay tier of 0 now means "stop pumping, freeze" instead of being floored to a 1Hz zombie that advanced the phase one full second per frame -- the visible "caustics freeze and tick at 1fps" report. A disconnected output also drops its stale `caustics` entry along with its other transient render state instead of leaking it under the connector name.
- `tidectl doctor`'s GPU check no longer FAILs on a machine with no GPU hardware at all, only when a GPU driver is actually loaded but exposes no render node (a real permissions/config problem). This unconditionally failed CI's own headless smoke test (no `/dev/dri` on a GitHub Actions runner), which is exactly the scenario the check should skip cleanly rather than flag.
- The backdrop effects (Ocean canvas grid, caustics, and BelowWindows ripples) now render above any wallpaper engine, not just the built-in wallpaper. They were spliced after the main desktop walk, but awww/swww/swaybg/hyprpaper (and video wallpapers) attach as layer-shell Background surfaces *inside* that walk -- so the grid and caustics rendered behind the wallpaper, invisible with a custom wallpaper while the built-in one happened to work because it was spliced even later. They now ride inside `desktop_render_elements`, spliced between the windows and the Bottom/Background layer surfaces, so they appear above whatever wallpaper engine is attached; the built-in wallpaper stays backmost as the fallback.
- Glass windows (water/frost) render at their real z-slot instead of being hoisted above everything. The glass layer + window surface were prepended ahead of the whole desktop walk, which put the aqua wave over layer-shell bars and other windows. Each window's glass layer is now inserted directly behind its own surface in the normal walk (surface -> glass -> shadow), so a glass window sits among windows and under chrome like any other. This also fixed the glass backdrop capture, which pushed the wallpaper *first* (topmost) into the captured texture -- the glass sampled a texture that was nothing but wallpaper, reading as "the aqua wave only shows the background and ignores everything else."
- The wheel/trackpad Ocean zoom no longer drifts toward the top-left edge on long scroll gestures. `zoom_at` computed endpoints that both preserved the world point under the viewport anchor, but the in-flight motion interpolated origin linearly while zoom interpolated geometrically -- the sampled world point under the anchor drifted toward smaller world coordinates mid-flight (AM >= GM on the inverse zooms), and a rapid wheel event that retargeted an in-flight motion baked that transient bias into the next motion's endpoints, accumulating drift per step. The motion now carries the anchor invariant and derives origin from the interpolated zoom, so the anchor holds at every instant, not just at the endpoints. Unit test samples five mid-animation instants and asserts the world point under the anchor never moves.
- The minimap now draws a crosshair at the pointer position, so aiming a click doesn't mean guessing where the map position is. It also renders *over* the map, not beneath it -- the first version pushed the glyph after the map, and with the front-to-back (index 0 topmost) convention it ended up behind the translucent panel, visible only as a faint ghost.
- `tidectl doctor`'s portal check no longer false-positives on a machine legitimately running another desktop: it compares the portal frontend's `XDG_CURRENT_DESKTOP` against the active session's instead of hardcoding "must be tidewm", and it reads the frontend's environment via `systemctl --user show MainPID` rather than a bare `pgrep` that can match a leftover per-desktop backend (whose stale env is meaningless). The check caught this machine's real staleness -- a Hyprland-era portal frontend still carrying the old desktop's env after a session switch -- correctly.

- `resize-to-monitor` sized the focused Ocean floating window to the output's raw resolution, pushing its border stroke past the visible screen edge -- the border draws outside the window's configured rect, not inside it. Now insets the target rect by `gaps`, the same margin `toggle-border-fullscreen` already applies to its own target.
- A dragged tiled Ocean window was rendering fixed at its original slot for the whole gesture, only ever appearing to move at the moment of the drop. Smart tiling keeps modifier-left drags of reef windows inside the tiling tree for tile-to-tile swaps (added this same span), and the tree stays frozen for the gesture's duration so the drop math has a stable slot to compare against -- but Ocean's renderer reads placement from that tree, never from `Space`'s live position, the same "`Space` is an input/protocol cache in Ocean, not spatial ownership" rule the S3 foundation established. The drag wrote its live position into `Space` (fine for hit-testing) but nothing carried it into the render path. `OceanSpace::set_tile_drag` now overrides the dragged window's placement rectangle directly for the gesture's duration (the same mechanism a genuinely floating window's own rect already gets), lifting it to the front as `PlacementKind::Floating` for the drag so it renders like it's picked up out of the grid -- note for anyone with `floating_only = true` on border/shadow/rounding: those now apply to the dragged window only while the drag is in progress, which is the intended "lifted out" read but is a side effect of the kind flip worth knowing about. Compile, clippy, fmt, and the 211-test suite pass; the drag itself is not live-verified -- nested winit provides no pointer-drag injection, the same documented limitation viscosity, connected-vessel resize, sway, and cascade resize all carry. - Cascade layout (`LayoutAlgorithm::Cascade`, `src/tide_core/layout.rs`), a third tiling algorithm alongside BSP and master, and the render roadmap's last unbuilt identity feature (renamed from its working name "basin-fill" in a design conversation with the maintainer). Windows wrap left to right, top to bottom into rows; the row count is chosen by scoring every candidate from one to the window count and picking whichever makes the resulting grid's column/row ratio land closest to the output's own aspect ratio, so an ultrawide monitor gets fewer, wider rows and a portrait one gets more, narrower ones. Row heights and each row's cell widths are computed from whatever space remains, the same rounding-gap-free pattern `layout_master`'s stack already uses on one axis, applied here on both. `default_layout = cascade` and the `layout:cascade` action select it; no default keybind is bound to it. Unit tests cover the zero/one-window cases, exact full-area tiling with no gap or overlap across a run of window counts on a non-round output size, row-count adaptation across wide/ultrawide/portrait aspect ratios, and the front-loaded remainder distribution. Verified live in a nested session: five real `kitty` clients on a near-square output landed in the predicted 3-row `[2, 2, 1]` arrangement.
- IPC event-stream/subscribe mode (`src/tide_core/ipc.rs`), Phase R3 of the render/visual-identity roadmap. The control socket was request-response only before this; it now also accepts `{"request": "subscribe", "events": [...]}` on a fresh connection, converting it into a long-lived push connection instead of a one-shot reply -- the intended path for a reactive widget (a waybar module, an eww `deflisten`, a QuickShell socket reader) that shouldn't have to poll `outputs`/`workspaces`/`windows`/`focused-window`. Omitting `events` (or sending an empty list) subscribes to all six channels; the ack echoes the resolved channel list so a typo'd filter is visible at handshake instead of silently matching nothing. Six emit chokepoints fire `window-opened`/`window-closed`/`window-changed`, `workspace-changed`, `focus-changed`, `urgent-changed`, `depth-changed`, and `config-reloaded` exactly where each becomes authoritative, not from the interactive keybind paths that happen to trigger them. - Optional floating-window sway (`src/visual/sway.rs`), the last mechanical Phase R2 slice. Dragging a floating window sideways now kicks a damped lateral oscillation, so the window swings side to side and settles back like it is sitting in water while the pointer keeps full authority over its real position. Two further R1 pieces remain after this: the impulse-ripple primitive and the first-pass depth/buoyancy model.
- Backdrop capture (`src/visual/backdrop.rs`), Phase R0.5 of the render/visual-identity roadmap: `capture_backdrop` renders whatever sits behind a floating window's rect into an offscreen texture, the shared plumbing both the familiar frosted-glass blur and TideWM's own water-glass refraction will sample from once their shaders land (Phase R1/R2). `desktop_render_elements` gained a `skip` parameter so the "behind" list is built by walking the real element composition with the target window omitted, not by filtering an already-built list -- the same front-to-back z-order this project's session-lock element-order bug already burned once. Capture runs after the visible frame submits (same FBO-only timing `render_pending_captures`'s screenshot capture already established as safe -- interleaving offscreen work before `submit()` previously broke the winit backend's context lifecycle, confirmed live), so a captured backdrop is one frame behind, consumed building the *next* frame -- the same latency real blur-behind implementations elsewhere accept. Captured textures are stored per-window (`Smallvil::backdrop_textures`) and evicted on unmap/destroy alongside `window_opacity`. Nothing samples the stored texture yet -- capture and storage only, gated on the existing `water_effects` toggle (its first real reader). Verified live in a nested session: the captured region's content matched the real screen at the same position and orientation (a distinctly asymmetric wallpaper shape lined up exactly, ruling out the y-flip this codebase has hit once before in the screenshot capture path), the target window's own content was correctly absent from its own backdrop, and the visible frame was unaffected. Checked PSS/CPU across 10 floating-window open/toggle-floating/close cycles: flat, no growth, confirming the eviction path actually prevents the leak a `HashMap<WlSurface, GlesTexture>` would otherwise accumulate. Two open items, see AGENT.md's roadmap section for detail: a faint, unchased residual in the capture-vs-screenshot diff (concentrated on wallpaper detail, not spread uniformly), and fractional output scale is unverified since `scale` overrides are udev-only and this session's testing was nested-only.
- `Animation`, a small shared linear-interpolation primitive (`src/visual/animation.rs`) -- the first piece of the render/visual-identity roadmap (AGENT.md's "Render and visual identity roadmap", Phase R0). Before this, nothing in the codebase interpolated a value over time at all; `toast.rs`'s fade was hand-rolled elapsed-time arithmetic, now rebuilt on top of this instead. `Smallvil::has_active_animation()` (`state.rs`) also replaces the toast-specific redraw check both backends used to duplicate, giving future water/decoration effects one shared place to plug into instead of each growing its own copy in `winit.rs` and `udev.rs`. No user-visible behavior change -- verified live in a nested session via `grim` screenshots: the config-reload toast still shows at full opacity and still fully clears once its lifetime elapses; a shot taken partway through the fade window showed visible partial transparency (not a hard cutoff), though the exact alpha at that point wasn't pinned to a known instant given unmeasured watcher-debounce latency between the config touch and the toast actually starting. Also checked PSS/CPU across 10 rapid trigger cycles (release build, nested): PSS settled ~10MB above pre-first-toast baseline (the toast's own rasterized texture, expected, not this change) and stayed flat across all 10 further triggers rather than climbing per-cycle, CPU stayed ~1.1-1.7% the whole time including mid-fade, and dropped back to the same idle baseline after each toast cleared rather than staying elevated -- no leak, no stuck redraw loop.
- The urgent-hint ripple trigger, the last of the three documented in AGENT.md's Phase R1 entry. Wired into `mark_urgent`, the existing downgrade path for an `xdg-activation-v1` request with a present-but-stale serial (declines to steal focus, marks the window urgent instead). Single-shot for now, matching the map/focus triggers -- a repeating "pulse until acknowledged" is later scope. Verified live with a throwaway two-window `smithay-client-toolkit` test client: map window A (capture its keyboard-enter serial), map window B (steals focus, staling A's serial), activate A with the now-stale token -- confirmed `fresh=false` and a `trigger=Urgent` ripple spawn via TideWM's own debug trace.

### Changed
- Reorganized the Rust source tree by responsibility without changing public behavior. Configuration, state, input, layout, IPC, and the Waves parser now live under `src/tide_core/`; animation, water/decorative effects, and compositor-owned visual UI now live under `src/visual/`. Crate-root re-exports preserve the established internal module paths, keeping this a file-layout change rather than a broad semantic rewrite. Backends, protocol handlers, pointer grabs, capture, screencasting, accessibility, cursor handling, and XWayland remain in their existing locations.

### Fixed
- Ocean IPC state now reflects Ocean ownership instead of leaking Classic/Smithay presentation caches. `outputs` reports `active_workspace: null` plus the live `camera_origin`, `workspaces` is empty because Ocean has no real workspaces, and window entries consistently report `workspace: null`, `output: null`, their non-owning `entry_output` hint, and the real Ocean floating state. A nested two-reef test caught the old inconsistency: a home-reef window appeared output-owned only because its world rectangle happened to overlap the output's presentation coordinates, while an equally valid deep-reef window reported no output and a successful floating conversion still reported `floating: false`.
- Waves bindings are now fully authoritative. Parsed files begin with empty bind and submap tables, so built-in and feature-specific bindings never remain active underneath a user's declarations. Ordinary keys can be held as user-defined helper modifiers in multi-key chords (`P+H`, `P+Ctrl+H`), multiple helper layers can coexist, and bare actions such as `F = toggle-fullscreen` are valid. `Ctrl+Alt+Escape` remains outside the configurable table as the recovery invariant: it temporarily activates known-safe fallback bindings in memory until a successful reload or restart, without rewriting the user's file. The generated example uses Alt as its main modifier, Super for workspaces, Ctrl for Ocean movement, and P as an ordinary helper key; those are examples rather than compositor policy.
- Ocean pointer focus now follows the model-neutral placement order, fixing clicks and hover focus passing through a visually topmost floating window to a tiled window below it. `input.unfocus_on_empty = true` optionally clears keyboard focus when the pointer moves onto empty desktop or Ocean canvas; it defaults off.
- A newly-mapped window matching a placement window rule (`float`, `pin`, `maximize`, `fullscreen`, `pseudo_tile`, or the auto-float heuristic) could receive two protocol configures in quick succession -- the ordinary tiled-size one from `retile()`, then a different-sized one from the placement conversion -- visible on a terminal as a one-frame garble/re-flow of its text grid. `map_toplevel` now withholds the first configure, but only when a second one is guaranteed to follow (`rule.maximize`/`rule.fullscreen`/`rule.pseudo_tile`, or a float/pin/auto-float conversion carrying a rule-provided `position`/`size`); a plain float/pin/auto-float conversion with no rule-provided size still gets the tiled configure, since nothing else would configure it at all. Found on real AMD hardware.
- Locking the pointer (`wp-pointer-constraints-v1`, e.g. Minecraft's mouse look) left the system cursor visibly frozen at its last on-screen position instead of hidden, since neither the udev backend's frame render nor the screenshot/capture path checked for an active lock. Both now hide the cursor for the duration of a lock, the same as a client's own hide request. Found on real AMD hardware.
- The IPC event-stream's `depth` channel never reported a window resurfacing, only sinking. `note_depth_attention` (the immediate tier-zero reset on focus/keyboard input) reset the tier and requested a redraw but never emitted `DepthChanged` -- only the periodic `update_window_depths` tick did, and by the time that tick next ran, the tier was already back at zero with nothing to report as changed. Found by live-testing the just-added per-rule buoyancy override: a subscriber watched a window sink through tier 1 and tier 2 correctly, but switching focus back to it -- confirmed visually snapping back to live content in the same instant via a back-to-back action-plus-screenshot check -- produced no corresponding event. `note_depth_attention` now emits `DepthChanged { tier: 0 }` on an actual reset, matching the periodic path.
- Moving a floating frost/water-glass window no longer displays a backdrop captured for its previous position. Both backends now render the window-sized offscreen capture immediately before binding the visible output, so that same frame samples the current drag geometry while preserving the known winit rule that no FBO work may occur between visible bind and submit. Same-sized recaptures reuse the existing `GlesTexture` instead of allocating a new GPU buffer for every pointer-motion frame, removing the allocation churn that made frost drags hitch as well as the one-frame visual trail that looked like flicker.
- The generated ripple example said `color = #8EDDFF`, but Waves correctly treats a bare `#` as the start of a comment, so uncommenting that line passed an empty value to the color parser. The example now uses bare `8EDDFF`; quoted `"#8EDDFF"` remains valid when keeping the prefix matters. `DOCUMENTATION.md` now carries the complete ripple reference instead of leaving the generated comments as the only catalog.
- The map-ripple's "droplet at the window's center" premise was wrong for ordinary tiled windows since the trigger first landed: `retile()` only sends a configure proposing a tiled window's new size, it doesn't wait for the client to ack and commit a matching buffer, so reading `window.geometry()` synchronously right after (as the map trigger does) saw the window's pre-tile size at its already-updated post-tile location. Every map ripple on a plain tiled window anchored near the gap offset (observed live: `(8, 8)`) instead of the window's real center. Same class of bug as `TileMoveGrab::drop`'s documented "space reflects where this is being moved to, not its real slot" gap; fixed the same way, reading the window's rect from `Layouts::layout()` (the same authoritative target `retile()` itself just computed) instead of `window.geometry()` when the window is tiled and not fullscreen/pseudo-tiled. First-map floating conversions had the same lag through a different path; they now anchor from `FloatingTag::rect`, which already holds the configure target, including an exact rule-provided position and size.
- `ripple { color = #RRGGBB }` silently failed to parse unless quoted: `config.wave`'s grammar strips a bare `#` as a comment outside quotes, so the documented hex syntax only ever worked as `color = "#RRGGBB"`. `parse_ripple_color` now also accepts bare `RRGGBB` (no quotes needed) and Hyprland-style `rgb(RRGGBB)`/`rgba(RRGGBB, AA)`, and a `debug`-level trace now logs a ripple's resolved trigger/color/shapes/layer at spawn so a config value silently not taking effect is distinguishable from the ripple not spawning at all.
- Forming a window group left a dead hole where the absorbed window's tile had been: `group_with` removed that window's leaf from the tree but never retiled, so the group kept its old smaller rect and the freed space sat on screen empty until some unrelated retile happened to run. Every other group path (ungroup, tab promotion, close-cleanup) already ends in a retile; this one now does too. Found during a live IPC-driven test pass on real hardware, where the hole stayed up for seconds until a layout switch healed it.
- Scratchpad entries in `tidectl workspaces` and `tidectl windows` now read `scratchpad` / `scratchpad:<name>` instead of leaking the synthetic internal workspace number (a named scratchpad printed as `workspace=4294963200`). The `windows` query's JSON also gained the same `scratchpad` field `workspaces` already had, so bars and scripts don't need to know the numbering scheme either.
- A live display-manager session logged nothing at all from the compositor: SDDM wires the session's stdout to `/dev/null` and only stderr into `wayland-session.log`, and `tracing_subscriber`'s `fmt()` writes to stdout by default. All logging now goes to stderr, where a session log can actually catch it.
- A screencast-enabled build froze the entire machine (mouse, keyboard, VT switch all dead, power-cycle needed) seconds into a real SDDM login. The startup check that restarts a stale `xdg-desktop-portal.service` ran synchronously before the event loop started -- and the restarted portal's own backend is a Wayland client of this compositor, so the portal waited for a compositor whose only thread was waiting for the portal. The restart job is now enqueued with `systemctl --no-block` and the compositor proceeds straight into its event loop. Root-caused from the journal of the frozen session (the portal stop/start lines were the last thing logged before the hard reset); the fix itself still needs a fresh SDDM login on real hardware to be called verified.

First pre-release. The milestone this number marks: the WM foundation is feature-complete and the core of it is now tested on real hardware — AMD end to end (including OBS/Discord screencasting on a standalone session), Nvidia through a full nested-backend pass on an RTX 3060. Next up is a code-optimization pass, then `render/` finally starts: the water effects TideWM exists for.

### Added
- Screencast portal now lists monitor, window, and virtual sources with a compositor-owned picker instead of grabbing the first monitor.
- Touchpad swipe/pinch gestures can trigger any compositor action. Verified live on real hardware (external USB Apple Magic Trackpad and a ThinkPad's built-in touchpad): all four swipe directions and `pinch_in` confirmed, `pinch_out` not yet confirmed. See AGENT.md's Phase M gesture section for the full account.
- Per-window `opacity` window rule.
- `xdg-toplevel-icon-v1` support.
- Named scratchpads: `toggle-scratchpad:<name>` / `move-to-scratchpad:<name>` action variants, any number of them, on top of the existing single scratchpad (which stays the bare `toggle-scratchpad`). Each name is just another reserved workspace under the hood -- same hide/show machinery, no new data structure. The IPC `workspaces` query tags scratchpad entries with a `scratchpad` name field so bars can label or hide them.
- Per-workspace and per-output gap overrides: repeatable `workspace_gaps = <N|name> <pixels>` lines (names resolve through `workspace_name` aliases) and a `gaps` key inside `output` blocks. Workspace beats output beats the global `gaps`.
- Window swallowing: a tiled window matching a `swallow = true` window rule is hidden when a window its process spawned maps, and that child takes over its exact tile; closing the child puts it back in the same slot. PID ancestry is read from `/proc`, so it works for any terminal without shell integration. Verified live in a nested session with grim screenshots: exact-slot replacement and restore, uninvolved tiles untouched.

### Fixed
- Fullscreen windows no longer render beneath layer-shell bars/launchers, in both live frames and screenshots.
- A crashed session-lock client now fails closed (the compositor exits) instead of leaving the session in an unclear state.
- PipeWire screencasting now actually produces frames. The producer stream never called `pw_stream_trigger_process()`, which a `StreamFlags::DRIVER` stream needs to start each graph cycle, so `process()` simply never fired. Verified under the nested winit backend against a real PipeWire daemon with a direct consumer: correct, live-updating frames over the MemFd/SHM path, PSS flat over a sustained stream. See AGENT.md's Screencasting section for the full root-cause writeup.
- Real OBS screencasting over the udev/DRM backend, on real hardware, fixed and verified live: OBS's log showed `pipewire: ... error: no more input formats` (a PipeWire negotiation error), but the actual bug was one level up, in `xdg-desktop-portal.service` itself. A systemd `--user` manager that outlives a session switch (SDDM "switch session", any relogin that doesn't tear the user manager down) keeps whatever `xdg-desktop-portal.service` instance was already running from the previous login, with the previous desktop's `XDG_CURRENT_DESKTOP` baked into its own already-running process environment -- `dbus-update-activation-environment`/`systemctl --user import-environment` (already correct, see the "Session environment" section of AGENT.md) only affect *future* activations, not a process already running. Confirmed live on this machine: the frontend had `XDG_CURRENT_DESKTOP=Hyprland` in `/proc/<pid>/environ` from an earlier Hyprland login on the same systemd user manager, silently routing every screencast request (OBS included) to `xdg-desktop-portal-hyprland` instead of this compositor's own backend -- with no error anywhere on TideWM's side to see, since the request never reached it. `main.rs` now detects this (checks the running frontend's actual `/proc` environment, not just the activation environment) and restarts only the frontend, once, at startup, when it's stale. Discord's own screen-share also confirmed working end to end on the same real hardware session.

- Keys no longer get stuck "held" in a nested session when the host compositor takes keyboard focus mid-chord (e.g. the host's own Super+L lock shortcut): the release the host swallowed left xkb's modifier state -- and the `wl_keyboard.modifiers` every client is told -- carrying a phantom Super, so plain drags acted as Super-drags and kitty decoded typing as CSI-u escape sequences. On host focus loss TideWM now synthesizes releases for everything still marked pressed, the same all-released semantics `wl_keyboard.leave` implies. Found by the Nvidia nested test pass, which also identified the root cause.
- Resizing the nested window (or applying a wlr-output-management transform/scale change) now actually retiles: the layer map's cached usable-area zone was only ever recomputed on layer-surface events, so `retile()` faithfully laid tiles out into the *old* output size while the wallpaper filled the new one. Reproduced live with a host-side resize, fixed by arranging the layer map at both mode-change sites.
- The nested backend now queries the host monitor's real refresh rate (was hardcoded 60Hz for both the advertised mode and the render-loop cadence -- the loop stays a bounded timer, just at the real rate), forwards the host's real scale factor including fractional (was always 1, which mis-sized anything DPI-aware on a scaled host monitor), and titles its window "TideWM" instead of the "Smithay" default.
- Screenshots taken inside a nested (winit) TideWM session are no longer vertically flipped. The output-capture render inherited the output's advertised transform, and the winit backend advertises `Flipped180` purely to cancel its EGL surface's y-orientation at present time -- baking that into the offscreen capture texture inverted the readback. Output captures now render with an explicit `Normal` transform, same as the window-capture path always did, and the capture privacy black-out rects follow the same transform so they stay aligned. Verified with grim in a nested session, full-output and region captures both. The udev backend (a normal, unrotated output) was never affected. Nested screencast frames shared the same pixels, so their orientation changes identically; real OBS/Discord screencasting was verified on udev and is untouched.

### Known issues
- DMA-BUF export is still disabled and still fails on real hardware, unrelated to the fixes above; MemFd/SHM is the supported transport.
- Portal virtual sources mirror the desktop instead of creating a real headless output.
- winit 0.30.13 (upstream, nested backend only) can panic with `failed to get pointer data` when the host changes seat capabilities under it (seen with a host session lock); crashes the nested dev process, not fixable from TideWM's side.
- A lone tiled window not filling the output, seen once in the Nvidia nested pass on a 125% host monitor, could not be reproduced at scale 1 and is plausibly the scale bug fixed above; needs a retest on a fractional-scale host.
